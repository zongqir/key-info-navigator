# 排序系统设计说明

## 概述

排序系统（Sorter）是一个独立的模块，用于对格式化文本项（FormattedTextItem）进行排序。该系统采用策略模式设计，支持多种排序方式，并且易于扩展。

## 目录结构

```
src/modules/sorter/
├── interfaces.ts              # 接口定义和枚举
├── BaseSorter.ts             # 排序器基类
├── SorterFactory.ts          # 排序器工厂
├── sorters/                  # 具体排序器实现
│   ├── RenderOrderSorter.ts  # 渲染顺序排序器
│   ├── BlockIdSorter.ts      # Block ID 排序器
│   └── UpdateTimeSorter.ts   # 更新时间排序器
└── index.ts                  # 模块导出
```

## 排序策略

### 1. 渲染顺序排序 (RENDER_ORDER) ✅ 已实现

根据块在文档中的实际渲染位置进行排序。这是**默认排序方式**。

**实现逻辑：**
- 优先从 DOM 中获取块的实际渲染位置
- 如果 DOM 不可用，从数据库查询块的创建时间（`created`）作为位置参考
- 同一块内的项目按 `position` 排序

**使用场景：**
- 希望列表顺序与文档渲染顺序一致
- 用户浏览时更符合阅读习惯

### 2. Block ID 排序 (BLOCK_ID) ✅ 已实现

根据 `blockId` 字符串本身进行字母排序。

**实现逻辑：**
- 使用 `localeCompare` 进行字符串比较
- 同一块内的项目按 `position` 排序

**使用场景：**
- 需要稳定的、可预测的排序顺序
- 调试时查找特定块

### 3. 更新时间排序 (UPDATE_TIME) ✅ 已实现

根据块的更新时间进行排序（最新的在前）。

**实现逻辑：**
- 从数据库查询块的更新时间（`updated` 字段）
- 按时间戳降序排列（新的在前）
- 同一块内的项目按 `position` 排序

**使用场景：**
- 快速找到最近修改的内容
- 按工作时间顺序浏览

## 核心接口

### SortStrategy 枚举

```typescript
export enum SortStrategy {
    RENDER_ORDER = "render_order",  // 渲染顺序
    BLOCK_ID = "block_id",          // Block ID
    UPDATE_TIME = "update_time"     // 更新时间
}
```

### ISorter 接口

```typescript
export interface ISorter {
    readonly strategy: SortStrategy;
    sort(items: FormattedTextItem[]): Promise<FormattedTextItem[]>;
}
```

## 扩展指南

### 添加新的排序策略

如果将来需要添加新的排序方式，按以下步骤操作：

#### 步骤1: 添加枚举值

在 `interfaces.ts` 中添加新的枚举值：

```typescript
export enum SortStrategy {
    RENDER_ORDER = "render_order",
    BLOCK_ID = "block_id",
    UPDATE_TIME = "update_time",
    CUSTOM_ORDER = "custom_order"  // 新增
}
```

#### 步骤2: 创建排序器类

在 `sorters/` 目录下创建新的排序器：

```typescript
// CustomOrderSorter.ts
import { BaseSorter } from "../BaseSorter";
import { SortStrategy } from "../interfaces";
import { FormattedTextItem } from "../../formatProcessor";

export class CustomOrderSorter extends BaseSorter {
    public readonly strategy = SortStrategy.CUSTOM_ORDER;
    
    public async sort(items: FormattedTextItem[]): Promise<FormattedTextItem[]> {
        // 实现自定义排序逻辑
        return items;
    }
}
```

#### 步骤3: 在工厂中注册

在 `SorterFactory.ts` 中添加 case：

```typescript
import { CustomOrderSorter } from "./sorters/CustomOrderSorter";

public static getSorter(strategy: SortStrategy): ISorter {
    switch (strategy) {
        // ... 现有的 case ...
        case SortStrategy.CUSTOM_ORDER:
            sorter = new CustomOrderSorter(SorterFactory.logger);
            break;
    }
}
```

#### 步骤4: 导出

在 `index.ts` 中导出新的排序器：

```typescript
export { CustomOrderSorter } from "./sorters/CustomOrderSorter";
```

## 设计优势

### 1. 单一职责
每个排序器只负责一种排序策略，代码清晰易维护。

### 2. 开放封闭
- 对扩展开放：可以轻松添加新的排序策略
- 对修改封闭：添加新策略不需要修改现有代码

### 3. 依赖倒置
通过接口 `ISorter` 进行交互，降低耦合度。

### 4. 工厂模式
- 统一创建和管理排序器实例
- 自动缓存实例，避免重复创建
- 提供默认排序器

### 5. 异步支持
所有排序方法都是异步的，支持需要数据库查询的排序策略。

## 性能优化

### 实例缓存
工厂模式自动缓存排序器实例，避免重复创建。

### DOM vs 数据库
渲染顺序排序器优先使用 DOM（速度快），只在必要时查询数据库。

### 批量查询
数据库查询使用 `IN` 语句进行批量查询，减少请求次数。
